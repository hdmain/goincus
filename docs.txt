goincus API reference
=====================

NAT VPS provisioning API on Incus (LXC containers).
Default listen: http://HOST:9603
Config: /etc/goincus/config.yaml
Content-Type: application/json


------------------------------------------------------------------------------
AUTH
------------------------------------------------------------------------------

Required on all endpoints except health:

  Authorization: Bearer <api_key>
  or
  X-API-Key: <api_key>

Keys live in config auth.api_keys (generated by: goincus init).
Failed auth is rate-limited per client IP.
Health endpoints are public (no key).


------------------------------------------------------------------------------
ENDPOINTS (summary)
------------------------------------------------------------------------------

  GET    /healthz
  GET    /api/v1/health

  GET    /api/v1/metrics?hours=24
  GET    /api/v1/hoststats
  GET    /api/v1/instances/
  POST   /api/v1/instances/
  GET    /api/v1/instances/{id|name}
  GET    /api/v1/instances/{id|name}/usage?days=30
  GET    /api/v1/instances/{id|name}/metrics?hours=24
  DELETE /api/v1/instances/{id|name}
  POST   /api/v1/instances/{id|name}/start
  POST   /api/v1/instances/{id|name}/stop
  POST   /api/v1/instances/{id|name}/restart
  POST   /api/v1/instances/{id|name}/repair
  POST   /api/v1/instances/{id|name}/ports
  DELETE /api/v1/instances/{id|name}/ports/{portID}

{id|name} accepts UUID or instance name.


------------------------------------------------------------------------------
ERRORS
------------------------------------------------------------------------------

JSON body:

  { "error": "message", "details": "optional" }

HTTP status:
  400  invalid input / bad JSON
  401  missing or invalid API key
  404  instance / port not found
  409  conflict (e.g. name already exists)
  429  auth rate limited
  500  internal error


------------------------------------------------------------------------------
INSTANCE STATUS
------------------------------------------------------------------------------

  pending    row created, not yet provisioning
  creating   Incus create / bootstrap in progress
  running    up with port block
  stopped    container stopped
  error      provisioning or lifecycle failed (see error_message)
  deleting   delete in progress
  deleted    soft-deleted (hidden from list/get)


------------------------------------------------------------------------------
NAT VPS MODEL (useful facts)
------------------------------------------------------------------------------

- Shared public IP of the host; no dedicated guest IP on the internet.
- Each VPS gets a contiguous host port block (default 20), mapped 1:1
  into the guest (public:N -> guest:N).
- SSH listens on the FIRST port of the block (not 22).
- Isolation: unprivileged LXC, no nesting, NIC filtering, port isolation,
  host disks hidden from lsblk, no guest->host SSH/API via bridge.
- Storage pool should be LVM or ZFS so guest df shows the VPS quota.

Port range defaults (config ports.*):
  host_range_start: 20000
  host_range_end:   29999
  ports_per_instance: 20


------------------------------------------------------------------------------
RESOURCE LIMITS
------------------------------------------------------------------------------

cpu_cores
  Fractional OK (e.g. 0.5). Whole cores pin via cpuset; fractions use
  Incus hard CFS quota (limits.cpu.allowance, e.g. 50ms/100ms for 0.5).

memory_mb
  Hard RAM cap (MiB). Min practical ~64.

storage_gb
  Root disk quota (GiB).

bandwidth_mbps
  eth0 rate cap both directions (Incus limits.max). 0 = unlimited.

traffic_monthly_gb
  Calendar-month UTC transfer quota (rx+tx GiB). 0 = unlimited.
  Over quota -> NIC throttled to ~8kbit until next UTC month.

Create request sentinels (body fields):
  0  = use server defaults from config defaults.*
  -1 = unlimited (bandwidth_mbps / traffic_monthly_gb only)

Config defaults (example):
  cpu_cores: 1
  memory_mb: 512
  storage_gb: 10
  processes: 512
  bandwidth_mbps: 100
  traffic_monthly_gb: 1024


------------------------------------------------------------------------------
1) HEALTH
------------------------------------------------------------------------------

GET /healthz
GET /api/v1/health

Auth: none
Status: 200

Response:
  {
    "status": "ok" | "degraded",
    "database": "up" | "down",
    "redis": "up" | "down",
    "incus": "up" | "down",
    "checks": { "database": "...", ... }   // optional error details
  }


------------------------------------------------------------------------------
2) LIST INSTANCES
------------------------------------------------------------------------------

GET /api/v1/instances/

Auth: required
Status: 200

Notes:
  - root_password is ALWAYS empty on list (fetch one instance to read it).
  - Returns [] when empty.

Response: array of Instance (see schema below).


------------------------------------------------------------------------------
3) CREATE INSTANCE
------------------------------------------------------------------------------

POST /api/v1/instances/

Auth: required
Status: 202 Accepted (async provisioning)

Body:
  {
    "name": "web-1",                 // required: 3-63 chars, [a-z][a-z0-9-]*[a-z0-9]
    "image": "ubuntu/24.04",         // optional
    "cpu_cores": 1,                  // optional; fractions OK; 0 = default
    "memory_mb": 512,                // optional; 0 = default
    "storage_gb": 10,                // optional; 0 = default
    "processes": 512,                // optional; 0 = default
    "bandwidth_mbps": 100,           // optional; 0 = default; -1 = unlimited
    "traffic_monthly_gb": 1024       // optional; 0 = default; -1 = unlimited
  }

Response: Instance (status usually "creating"; ports may be empty until ready).
Includes root_password.

Poll GET until status == "running" and ports are present.


------------------------------------------------------------------------------
4) GET INSTANCE
------------------------------------------------------------------------------

GET /api/v1/instances/{id|name}

Auth: required
Status: 200

Response: Instance including root_password, ports[], traffic_* fields.
Status is refreshed from Incus when possible.


------------------------------------------------------------------------------
5) USAGE CHART (daily disk + bandwidth)
------------------------------------------------------------------------------

GET /api/v1/instances/{id|name}/usage?days=30

Auth: required
Status: 200

Query:
  days  lookback ending today UTC (default 30, max 366)

Sampling:
  - Written automatically in the background (UTC calendar day).
  - disk_*: snapshot of root usage / quota.
  - bandwidth_bytes: rx+tx transferred that UTC day.
  - Missing days are filled (bandwidth 0; disk carries last known / quota).
  - Retention ~400 days.

Response:
  {
    "instance_id": "uuid",
    "name": "web-1",
    "days": 30,
    "from": "2026-09-05",
    "to": "2026-10-04",
    "points": [
      {
        "date": "2026-10-04",
        "disk_used_bytes": 790630400,
        "disk_total_bytes": 5368709120,
        "bandwidth_bytes": 1234567
      }
    ]
  }


------------------------------------------------------------------------------
5b) HOURLY METRICS (CPU / RAM / disk / bandwidth)
------------------------------------------------------------------------------

GET /api/v1/metrics?hours=24
GET /api/v1/instances/{id|name}/metrics?hours=24

Auth: required
Status: 200

Query:
  hours  lookback ending current UTC hour (default 24, max 2160)

Config (usage.* in /etc/goincus/config.yaml):
  sample_interval: 1m          # monthly traffic + daily samples
  hourly_enabled: true         # store CPU/RAM/disk/bandwidth for every VPS
  hourly_interval: 1h          # how often to write hourly buckets
  hourly_retention_days: 30
  daily_retention_days: 400

GET /api/v1/metrics returns all instances on this node.
Per-instance path filters to one VPS.

Response:
  {
    "hours": 24,
    "from": "2026-10-03T18:00:00Z",
    "to": "2026-10-04T17:00:00Z",
    "items": [
      {
        "instance_id": "uuid",
        "name": "web-1",
        "points": [
          {
            "hour": "2026-10-04T17:00:00Z",
            "cpu_percent": 12.5,
            "memory_used_bytes": 120000000,
            "memory_total_bytes": 268435456,
            "disk_used_bytes": 790630400,
            "disk_total_bytes": 5368709120,
            "bandwidth_bytes": 4500000
          }
        ]
      }
    ]
  }

cpu_percent is relative to the instance CPU allocation (100 = fully using its cores).
bandwidth_bytes is rx+tx transferred in that hour bucket.


------------------------------------------------------------------------------
5c) HOST STATS (free ports + free disk)
------------------------------------------------------------------------------

GET /api/v1/hoststats

Auth: required
Status: 200

Node capacity for this host:
  ports  free/used/total in ports.host_range_* (DB allocations)
  disk   free/used/total on the active Incus storage pool

Response:
  {
    "ports": {
      "range_start": 20000,
      "range_end": 29999,
      "ports_per_instance": 20,
      "total": 10000,
      "used": 40,
      "free": 9960
    },
    "disk": {
      "pool": "goincus",
      "driver": "lvm",
      "total_bytes": 214748364800,
      "used_bytes": 21474836480,
      "free_bytes": 193273528320
    }
  }


------------------------------------------------------------------------------
6) DELETE INSTANCE
------------------------------------------------------------------------------

DELETE /api/v1/instances/{id|name}

Auth: required
Status: 204 No Content

Removes Incus container, releases port block, soft-deletes DB row.


------------------------------------------------------------------------------
7) START / STOP / RESTART / REPAIR
------------------------------------------------------------------------------

POST /api/v1/instances/{id|name}/start
POST /api/v1/instances/{id|name}/stop
POST /api/v1/instances/{id|name}/restart
POST /api/v1/instances/{id|name}/repair

Auth: required
Status: 200
Response: Instance

start
  Starts container; re-applies resource limits / disk isolation;
  ensures port block + SSH bootstrap if needed.

stop
  Stops container.

restart
  Restarts container.

repair
  Best-effort fix: limits, isolation, network, ports, SSH.
  Returns root_password.


------------------------------------------------------------------------------
8) ADD PORT
------------------------------------------------------------------------------

POST /api/v1/instances/{id|name}/ports

Auth: required
Status: 201 Created

Body:
  {
    "protocol": "tcp",          // "tcp" or "udp"
    "internal_port": 8080,      // guest listen port
    "host_port": 0              // optional; 0 = allocate from configured range
  }

Notes:
  Default create already maps a full 1:1 block. Extra ports are for
  additional mappings outside that auto block when allocation allows.

Response: PortMapping.


------------------------------------------------------------------------------
9) REMOVE PORT
------------------------------------------------------------------------------

DELETE /api/v1/instances/{id|name}/ports/{portID}

Auth: required
Status: 204 No Content

portID is the PortMapping UUID from get/list.

------------------------------------------------------------------------------
CLI (talks to the same API)
------------------------------------------------------------------------------

  goincus health
  goincus list
  goincus get <name|id>
  goincus create <name> [-cpu] [-memory] [-disk] [-bandwidth] [-traffic] [-image] [-wait]
  goincus start|stop|restart|repair <name|id>
  goincus usage <name|id> [-days 30] [-json]
  goincus metrics [name|id] [-hours 24] [-json]
  goincus hoststats [-json]
  goincus ssh <name|id> [-host YOUR.PUBLIC.IP]
  goincus delete <name|id> [-y]

Flags / env:
  -url / GOINCUS_URL          default http://127.0.0.1:9603
  -key / GOINCUS_API_KEY      or first key from config
  -config / GOINCUS_CONFIG    default /etc/goincus/config.yaml
  -json                       raw JSON output
  GOINCUS_SSH_HOST            host printed by `goincus ssh`

CURL EXAMPLES
------------------------------------------------------------------------------

# Health
curl -s http://127.0.0.1:9603/healthz

# Create
curl -s -X POST http://127.0.0.1:9603/api/v1/instances/ \
  -H "Authorization: Bearer gic_xxx" \
  -H "Content-Type: application/json" \
  -d '{"name":"web-1","cpu_cores":1,"memory_mb":512,"storage_gb":10,"bandwidth_mbps":100,"traffic_monthly_gb":1024}'

# Get
curl -s http://127.0.0.1:9603/api/v1/instances/web-1 \
  -H "Authorization: Bearer gic_xxx"

# Usage chart (daily)
curl -s "http://127.0.0.1:9603/api/v1/instances/web-1/usage?days=30" \
  -H "Authorization: Bearer gic_xxx"

# Hourly metrics — all VPS
curl -s "http://127.0.0.1:9603/api/v1/metrics?hours=24" \
  -H "Authorization: Bearer gic_xxx"

# Hourly metrics — one VPS
curl -s "http://127.0.0.1:9603/api/v1/instances/web-1/metrics?hours=24" \
  -H "Authorization: Bearer gic_xxx"

# Host capacity (free ports + free disk)
curl -s http://127.0.0.1:9603/api/v1/hoststats \
  -H "Authorization: Bearer gic_xxx"

# Stop / start
curl -s -X POST http://127.0.0.1:9603/api/v1/instances/web-1/stop \
  -H "Authorization: Bearer gic_xxx"
curl -s -X POST http://127.0.0.1:9603/api/v1/instances/web-1/start \
  -H "Authorization: Bearer gic_xxx"

# Delete
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE \
  http://127.0.0.1:9603/api/v1/instances/web-1 \
  -H "Authorization: Bearer gic_xxx"

------------------------------------------------------------------------------
FIREWALL (host)
------------------------------------------------------------------------------

Open API (if remote) and the VPS port range, e.g.:

  ufw allow 9603/tcp
  ufw allow 20000:29999/tcp

Prefer TLS reverse proxy in front of the API on the public internet.
